================================================================================
TIME -SERIES CROSS-VALIDATION (TSCV)
================================================================================

WHY TSCV?
  Traditional CV shuffles data → Data leakage in time-series
  TSCV respects temporal order → Parameters work across market regimes

HOW IT WORKS (n_cv_splits=3):
  ┌─────────────────────────────────────────────────────────────────┐
  │                                                                  │
  │  Fold 1: Train [Jan─Mar] → Validate [Apr]                       │
  │  Fold 2: Train [Jan─Jun] → Validate [Jul]                       │
  │  Fold 3: Train [Jan─Sep] → Validate [Oct]                       │
  │                                                                  │
  │  Final Score: Average of 3 folds                                │
  │                                                                  │
  └─────────────────────────────────────────────────────────────────┘

BENEFITS:
   Tests params across different periods (quiet vs volatile markets)
   Prevents overfitting to one specific time window
   More robust production performance

COST: ~3x slower than single split (still worth it!)

================================================================================
PRUNING (NEW FEATURE)
================================================================================

WHAT IS PRUNING?
  Optuna stops "obviously bad" trials early to save time.

  Example:
    Trial 10: MAPE at epoch 50 = 5.2% (terrible)
    Best so far: MAPE = 0.4%
    → Stop Trial 10 immediately (don't waste 200 more epochs)

TWO PRUNERS:
  1. MedianPruner: Compares trial to median of previous trials
  2. LightGBMPruningCallback: Monitors LightGBM validation score

IMPACT: ~40% time savings (e.g., 3 hours → 1.8 hours)

DISABLE IF:
  - Using very few trials (<20)
  - Early trials get pruned too aggressively (rare)

================================================================================
RISK SCORE OPTIMIZATION (CLASSIFIER)
================================================================================

TARGET CHANGED: is_stable → is_unstable
  - Old: 1 = Safe, 0 = Unsafe
  - New: 1 = Risk, 0 = Safe
  - HIGH SCORE = HIGH RISK (intuitive!)

METRIC CHANGED: F1 → binary_logloss
  - F1: Optimizes binary threshold accuracy
  - Log Loss: Optimizes probability calibration
  - Result: 20% score truly means 20% risk

NO scale_pos_weight:
  - Removed to ensure true probability calibration
  - Model learns natural class balance

BUSINESS IMPACT:
  - Decision engine can trust probabilities
  - Can combine with external interruption rates
  - Dynamic risk thresholds (e.g., "conservative during peak hours")

================================================================================
FAQ
================================================================================

Q: Why not use GridSearch?
A: GridSearch tests ALL combinations (slow). Optuna is smart (TPE sampler).

Q: Can I run HPO on full data?
A: Technically yes (--no-sampling), but 5x slower with minimal gain.

Q: Do I need to re-run HPO often?
A: No. Only when:
   - Adding major new features
   - Model architecture changes
   - Performance degrades significantly

Q: How many CV folds should I use?
A: 3 is good balance. 5 if you have time. More folds = more robust, but slower.

Q: Why systematic sampling instead of random?
A: Random breaks time-series continuity. Systematic preserves temporal patterns.
