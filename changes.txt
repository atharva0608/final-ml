### 1. The Database Model (Store the Daily Cache)

We need a table to cache the cost data so we don't spam the expensive AWS Cost Explorer API every time a user refreshes the dashboard.

**File:** `backend/models/billing.py` (Create this file)

```python
from sqlalchemy import Column, String, Float, DateTime, ForeignKey, Date
from sqlalchemy.orm import relationship
from backend.models.base import Base
from datetime import datetime

class DailyCost(Base):
    __tablename__ = "daily_costs"

    id = Column(String, primary_key=True)  # Format: "ACC-ID_YYYY-MM-DD_SERVICE"
    account_id = Column(String, ForeignKey("accounts.id"), nullable=False)
    date = Column(Date, nullable=False)
    service_name = Column(String, nullable=False)  # e.g., 'AmazonEC2', 'AmazonS3'
    cost_amount = Column(Float, default=0.0)
    currency = Column(String, default="USD")
    
    # Metadata for aggregation
    cost_type = Column(String, default="Usage") # 'Usage', 'Tax', 'Support'
    updated_at = Column(DateTime, default=datetime.utcnow)

```

### 2. The Cost Fetching Worker (The Logic)

This background task runs once every 24 hours (or 6 hours) to fetch the latest data from AWS Cost Explorer. It handles the "Total Cost" and "Breakdown" logic automatically by asking AWS to group the data.

**File:** `backend/workers/tasks/cost_calculator.py`

```python
import boto3
from datetime import datetime, timedelta
from sqlalchemy.orm import Session
from backend.models.base import SessionLocal
from backend.models.account import Account
from backend.models.billing import DailyCost
from backend.core.config import settings

def fetch_aws_costs(account_id: str, role_arn: str, region: str = "us-east-1"):
    """
    Connects to AWS Cost Explorer using the assumed role and fetches
    Daily costs grouped by Service.
    """
    # 1. Assume Role Logic (Standard STS)
    sts_client = boto3.client('sts', region_name=region)
    assumed_role = sts_client.assume_role(
        RoleArn=role_arn,
        RoleSessionName="CostExplorerSession"
    )
    credentials = assumed_role['Credentials']

    # 2. Initialize Cost Explorer Client
    ce = boto3.client(
        'ce',
        aws_access_key_id=credentials['AccessKeyId'],
        aws_secret_access_key=credentials['SecretAccessKey'],
        aws_session_token=credentials['SessionToken'],
        region_name=region
    )

    # 3. Define Time Window (Last 30 days)
    end = datetime.now().date()
    start = end - timedelta(days=30)
    
    # 4. Fetch Cost & Usage
    response = ce.get_cost_and_usage(
        TimePeriod={
            'Start': start.isoformat(),
            'End': end.isoformat()
        },
        Granularity='DAILY',
        Metrics=['AmortizedCost'], # 'AmortizedCost' accounts for RIs/Savings Plans correctly
        GroupBy=[{'Type': 'DIMENSION', 'Key': 'SERVICE'}]
    )
    
    return response['ResultsByTime']

def sync_costs_for_all_accounts():
    db: Session = SessionLocal()
    accounts = db.query(Account).filter(Account.status == 'ACTIVE').all()

    for acc in accounts:
        try:
            print(f"Fetching costs for {acc.name} ({acc.aws_account_id})...")
            results = fetch_aws_costs(acc.aws_account_id, acc.iam_role_arn)
            
            for day_data in results:
                date_str = day_data['TimePeriod']['Start']
                
                for group in day_data['Groups']:
                    service_name = group['Keys'][0]
                    amount = float(group['Metrics']['AmortizedCost']['Amount'])
                    
                    # Generate Unique ID to prevent duplicates
                    record_id = f"{acc.aws_account_id}_{date_str}_{service_name}"
                    
                    # Upsert Logic
                    cost_entry = db.query(DailyCost).filter_by(id=record_id).first()
                    if not cost_entry:
                        cost_entry = DailyCost(
                            id=record_id,
                            account_id=acc.id,
                            date=datetime.strptime(date_str, "%Y-%m-%d").date(),
                            service_name=service_name,
                            cost_amount=amount
                        )
                        db.add(cost_entry)
                    else:
                        cost_entry.cost_amount = amount # Update with latest accurate data
            
            db.commit()
            print(f"Successfully updated costs for {acc.name}")

        except Exception as e:
            print(f"Failed to fetch costs for {acc.name}: {str(e)}")
            db.rollback()
    
    db.close()

```

### 3. The Logic: Total Calculation & Breakdown (API Layer)

Now we create the API that sums up the database records to give you the `A + B` logic you asked for.

**File:** `backend/api/billing_routes.py`

```python
from fastapi import APIRouter, Depends
from sqlalchemy.orm import Session
from sqlalchemy import func
from backend.models.base import get_db
from backend.models.billing import DailyCost
from datetime import datetime, timedelta

router = APIRouter(prefix="/api/billing", tags=["billing"])

@router.get("/summary")
def get_cost_summary(db: Session = Depends(get_db)):
    """
    Returns the Total Month-to-Date Cost and the Compute vs. Database split.
    """
    # Define Month-to-Date Window
    today = datetime.utcnow().date()
    first_day_of_month = today.replace(day=1)

    # 1. Total Cost (Sum of all services)
    total_cost = db.query(func.sum(DailyCost.cost_amount))\
        .filter(DailyCost.date >= first_day_of_month)\
        .scalar() or 0.0

    # 2. Compute Cost (EC2 + EKS)
    compute_cost = db.query(func.sum(DailyCost.cost_amount))\
        .filter(DailyCost.date >= first_day_of_month)\
        .filter(DailyCost.service_name.in_(['Amazon Elastic Compute Cloud - Compute', 'Amazon Elastic Kubernetes Service']))\
        .scalar() or 0.0

    # 3. Resource/Storage Cost (RDS + S3 + EBS)
    # Note: EBS is often listed as 'EC2 - Other' or under EC2, but we can approximate via explicit service names
    resource_cost = db.query(func.sum(DailyCost.cost_amount))\
        .filter(DailyCost.date >= first_day_of_month)\
        .filter(DailyCost.service_name.in_(['Amazon Relational Database Service', 'Amazon Simple Storage Service']))\
        .scalar() or 0.0

    # 4. Service Breakdown (Top 5 Spenders)
    breakdown = db.query(DailyCost.service_name, func.sum(DailyCost.cost_amount).label('total'))\
        .filter(DailyCost.date >= first_day_of_month)\
        .group_by(DailyCost.service_name)\
        .order_by(func.sum(DailyCost.cost_amount).desc())\
        .limit(5)\
        .all()

    return {
        "period": "Month-to-Date",
        "total_cost": round(total_cost, 2),
        "compute_cost": round(compute_cost, 2),
        "resource_cost": round(resource_cost, 2),
        "other_cost": round(total_cost - compute_cost - resource_cost, 2),
        "top_services": [{"name": b[0], "cost": round(b[1], 2)} for b in breakdown]
    }

```

### 4. Implementation Steps for You

1. **Install Requirements**: Add `boto3` to your requirements.txt (it is likely already there).
2. **Enable Cost Explorer**: Ensure your AWS Account has "Cost Explorer" enabled in the AWS Console (it takes 24 hours to activate for new accounts).
3. **Update IAM Role**: The role `SpotOptimizerRole` (in your `templates/aws/full-access-role.yaml`) **MUST** have this permission added:
```yaml
- Effect: Allow
  Action:
    - "ce:GetCostAndUsage"
  Resource: "*"

```


*Without this permission, the fetch will fail.*
4. **Run Migration**: You need to create the `daily_costs` table. I can generate the Alembic migration script if you need it.
5. **Schedule Worker**: Add `sync_costs_for_all_accounts` to your Celery beat schedule in `backend/workers/app.py` to run every 12 or 24 hours.

### Why this logic is "Real":

* **Accurate**: It uses `AmortizedCost`, which spreads out one-time fees (like RI purchases) across the month, giving you a smooth daily burn rate rather than spikes.
* **Comprehensive**: It includes **everything** (Network transfer, Load Balancers, Secrets Manager), not just the instances you know about.
* **Practical**: It caches data locally. This means your dashboard loads instantly, and you don't pay AWS per-API-call fees every time a user navigates to the page.
