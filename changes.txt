Bug A-1 — OIDC Provider Never Created (Karpenter CrashLoopBackOff)
Root cause from your crash report: The IAM OIDC Identity Provider for the cluster was never registered in AWS IAM. STS rejects every IRSA token with InvalidIdentityToken: No OpenIDConnect provider found. This is the sole direct cause of the CrashLoopBackOff.
The backend's install_karpenter() route validates that KarpenterControllerRole and KarpenterNodeRole exist, but never checks whether the OIDC provider is registered. It proceeds with Helm install even when OIDC is missing.

# BEFORE deploying the agent DaemonSet (not just before Karpenter install)
def _ensure_oidc_provider(self, cluster_name: str, region: str, boto_session) -> str:
    """
    Creates the IAM OIDC Identity Provider for the cluster if it doesn't exist.
    Returns the OIDC issuer URL (without https://).
    Must be called before any IRSA-based workload (Karpenter, etc.) can work.
    """
    eks_client = boto_session.client('eks', region_name=region)
    iam_client = boto_session.client('iam')

    # Get cluster OIDC issuer
    cluster_info = eks_client.describe_cluster(name=cluster_name)
    oidc_issuer = cluster_info['cluster']['identity']['oidc']['issuer']
    oidc_host = oidc_issuer.replace('https://', '')
    # e.g. oidc.eks.ap-south-1.amazonaws.com/id/8C59A5F7D671AA9C87D7D03CC2BAE51E

    expected_arn = f"arn:aws:iam::{account_id}:oidc-provider/{oidc_host}"

    # Check if already exists
    existing = iam_client.list_open_id_connect_providers()
    existing_arns = [p['Arn'] for p in existing['OpenIDConnectProviderList']]
    if expected_arn in existing_arns:
        logger.info(f"OIDC provider already exists: {expected_arn}")
        return oidc_host

    # Get OIDC thumbprint (required by AWS API)
    thumbprint = _get_oidc_thumbprint(oidc_issuer)

    iam_client.create_open_id_connect_provider(
        Url=oidc_issuer,
        ClientIDList=['sts.amazonaws.com'],
        ThumbprintList=[thumbprint],
        Tags=[
            {'Key': 'ManagedBy', 'Value': 'SpotOptimizer'},
            {'Key': 'ClusterName', 'Value': cluster_name},
        ]
    )
    logger.info(f"Created OIDC provider: {expected_arn}")
    return oidc_host


def _get_oidc_thumbprint(oidc_issuer: str) -> str:
    """Fetch the TLS thumbprint of the OIDC provider endpoint."""
    import ssl, hashlib, urllib.request
    hostname = oidc_issuer.replace('https://', '').split('/')[0]
    ctx = ssl.create_default_context()
    with ctx.wrap_socket(
        __import__('socket').create_connection((hostname, 443)),
        server_hostname=hostname
    ) as s:
        cert = s.getpeercert(binary_form=True)
    return hashlib.sha1(cert).hexdigest()

Bug A-3 — EC2NodeClass Has No Architecture-Aware AMI Selection
This is the core dual-architecture bug. The EC2NodeClass currently uses a single AMI selector pattern that only works for one architecture. When NodePool allows both amd64 and arm64 (Graviton), Karpenter may launch ARM64 instances with an x86_64 AMI or vice versa, causing the node to fail to start.
Fix — EC2NodeClass must use amiSelectorTerms with architecture-specific AMI families, OR use AL2023 which supports both:
python# In agent/actuator.py _create_default_karpenter_resources()
# Replace the single EC2NodeClass with one that explicitly supports both architectures:

EC2_NODE_CLASS_TEMPLATE = """
apiVersion: karpenter.k8s.aws/v1
kind: EC2NodeClass
metadata:
  name: spot-optimizer-default
  annotations:
    spot-optimizer/managed: "true"
spec:
  # AL2023 supports BOTH amd64 AND arm64 — single AMI family for both archs
  amiFamily: AL2023
  
  # amiSelectorTerms with AL2023 lets Karpenter auto-select the correct
  # AMI for whatever architecture it provisions — no hardcoded AMI ID needed
  amiSelectorTerms:
    - alias: al2023@latest   # Karpenter resolves correct arch AMI automatically
  
  role: "KarpenterNodeRole-{cluster_name}"
  
  subnetSelectorTerms:
    - tags:
        karpenter.sh/discovery: "{cluster_name}"
  
  securityGroupSelectorTerms:
    - tags:
        karpenter.sh/discovery: "{cluster_name}"
  
  tags:
    ManagedBy: SpotOptimizer
    ClusterName: "{cluster_name}"
"""
Why AL2023 with alias: al2023@latest is the correct approach:

Karpenter resolves the AMI via SSM Parameter Store at provisioning time
It automatically picks x86_64 AMI for amd64 nodes and arm64 AMI for Graviton nodes
No hardcoded AMI IDs means no drift when new EKS AMIs are released
The amiFamily: AL2023 + alias is the Karpenter v1.x canonical way — amiSelectorTerms with static AMI IDs is the anti-pattern

Bug A-5 — WorkloadInspector Classification Doesn't Guard Architecture Compatibility
The WorkloadInspector correctly identifies STATELESS_ELIGIBLE nodes (no PVC, no StatefulSet, no hostPath). But it doesn't validate whether existing workloads have nodeSelector or affinity rules that pin them to a specific architecture.
If a Deployment has nodeSelector: kubernetes.io/arch: amd64, and you drain an amd64 node and Karpenter provisions an arm64 replacement, that pod will stay Pending forever.
Fix — add architecture affinity check to WorkloadInspector:
python# In backend/services/workload_inspector.py — add to classification logic:
def _has_arch_affinity(self, pod) -> str | None:
    """
    Returns the required architecture if the pod is pinned to a specific arch.
    Returns None if the pod can run on any architecture.
    """
    # Check nodeSelector
    if pod.spec.node_selector:
        arch = pod.spec.node_selector.get('kubernetes.io/arch')
        if arch:
            return arch
    
    # Check nodeAffinity
    affinity = pod.spec.affinity
    if affinity and affinity.node_affinity:
        required = affinity.node_affinity.required_during_scheduling_ignored_during_execution
        if required:
            for term in required.node_selector_terms:
                for expr in (term.match_expressions or []):
                    if expr.key == 'kubernetes.io/arch' and expr.operator == 'In':
                        return expr.values[0] if len(expr.values) == 1 else None
    return None

    arch = self._has_arch_affinity(pod)

# If empty → node workloads can run on any arch → Graviton replacement is safe

class ClusterCleanupService:
    """
    Automated cleanup of ALL AWS and Kubernetes resources created for a cluster.
    Called when DELETE /api/v1/clusters/{id} is invoked.
    Everything is idempotent — safe to call even if resources are partially missing.
    """

    def cleanup_cluster(
        self,
        cluster: Cluster,
        account: Account,
        boto_session,
        k8s_reachable: bool = True
    ):
        results = {}

        # 1. Kubernetes resources (if cluster is still reachable)
        if k8s_reachable:
            results['k8s'] = self._cleanup_kubernetes_resources(cluster, boto_session)

        # 2. AWS IAM resources
        results['iam'] = self._cleanup_iam_resources(cluster, boto_session)

        # 3. SQS queue
        results['sqs'] = self._cleanup_sqs_queue(cluster, boto_session)

        # 4. EventBridge rules
        results['eventbridge'] = self._cleanup_eventbridge_rules(cluster, boto_session)

        # 5. OIDC provider
        results['oidc'] = self._cleanup_oidc_provider(cluster, boto_session)

        # 6. Redis keys
        results['redis'] = self._cleanup_redis_keys(cluster.id)

        return results

    # ── Kubernetes ────────────────────────────────────────────────────

    def _cleanup_kubernetes_resources(self, cluster, boto_session):
        """
        Helm uninstall Karpenter + delete EC2NodeClass + NodePool CRDs.
        Runs via an AgentAction dispatched to the cluster's agent.
        """
        # Queue UNINSTALL_KARPENTER agent action (agent runs helm uninstall)
        action = AgentAction(
            cluster_id=cluster.id,
            action_type=AgentActionType.UNINSTALL_KARPENTER,
            payload={"cluster_name": cluster.name},
            timeout_seconds=120,
        )
        db.add(action)
        db.commit()
        return {"queued": "UNINSTALL_KARPENTER"}

    # ── IAM ───────────────────────────────────────────────────────────

    def _cleanup_iam_resources(self, cluster, boto_session):
        iam = boto_session.client('iam')
        cluster_name = cluster.name
        cleaned = []

        # 1. Delete KarpenterControllerRole
        self._delete_iam_role(iam, f"KarpenterControllerRole-{cluster_name}", cleaned)

        # 2. Remove KarpenterNodeRole from instance profile, then delete both
        profile_name = f"KarpenterNodeInstanceProfile-{cluster_name}"
        node_role_name = f"KarpenterNodeRole-{cluster_name}"
        try:
            iam.remove_role_from_instance_profile(
                InstanceProfileName=profile_name,
                RoleName=node_role_name
            )
        except iam.exceptions.NoSuchEntityException:
            pass
        try:
            iam.delete_instance_profile(InstanceProfileName=profile_name)
            cleaned.append(profile_name)
        except iam.exceptions.NoSuchEntityException:
            pass

        self._delete_iam_role(iam, node_role_name, cleaned)
        return {"deleted": cleaned}

    def _delete_iam_role(self, iam, role_name: str, cleaned: list):
        try:
            # Must detach managed policies before deleting
            attached = iam.list_attached_role_policies(RoleName=role_name)
            for p in attached['AttachedPolicies']:
                iam.detach_role_policy(RoleName=role_name, PolicyArn=p['PolicyArn'])
            # Must delete inline policies before deleting
            inline = iam.list_role_policies(RoleName=role_name)
            for p in inline['PolicyNames']:
                iam.delete_role_policy(RoleName=role_name, PolicyName=p)
            iam.delete_role(RoleName=role_name)
            cleaned.append(role_name)
        except iam.exceptions.NoSuchEntityException:
            pass  # Already gone — idempotent

    # ── SQS ──────────────────────────────────────────────────────────

    def _cleanup_sqs_queue(self, cluster, boto_session):
        sqs = boto_session.client('sqs', region_name=cluster.region)
        queue_name = f"KarpenterInterruptionQueue-{cluster.name}"
        try:
            url = sqs.get_queue_url(QueueName=queue_name)['QueueUrl']
            sqs.delete_queue(QueueUrl=url)
            return {"deleted": queue_name}
        except sqs.exceptions.QueueDoesNotExist:
            return {"skipped": "already gone"}

    # ── EventBridge ──────────────────────────────────────────────────

    def _cleanup_eventbridge_rules(self, cluster, boto_session):
        events = boto_session.client('events', region_name=cluster.region)
        cluster_name = cluster.name
        rule_names = [
            f"KarpenterRule-{cluster_name}-SpotInterruption",
            f"KarpenterRule-{cluster_name}-Rebalance",
            f"KarpenterRule-{cluster_name}-InstanceStateChange",
        ]
        cleaned = []
        for rule_name in rule_names:
            try:
                targets = events.list_targets_by_rule(Rule=rule_name)
                if targets['Targets']:
                    events.remove_targets(
                        Rule=rule_name,
                        Ids=[t['Id'] for t in targets['Targets']]
                    )
                events.delete_rule(Name=rule_name)
                cleaned.append(rule_name)
            except events.exceptions.ResourceNotFoundException:
                pass
        return {"deleted": cleaned}

    # ── OIDC Provider ────────────────────────────────────────────────

    def _cleanup_oidc_provider(self, cluster, boto_session):
        """
        Delete the IAM OIDC Identity Provider for this cluster.
        Only safe to delete when no other workloads in this account use it.
        Since each cluster has a unique OIDC hash, it's safe to delete per-cluster.
        """
        iam = boto_session.client('iam')
        eks = boto_session.client('eks', region_name=cluster.region)
        sts = boto_session.client('sts')
        account_id = sts.get_caller_identity()['Account']

        try:
            cluster_info = eks.describe_cluster(name=cluster.name)
            oidc_issuer = cluster_info['cluster']['identity']['oidc']['issuer']
            oidc_host = oidc_issuer.replace('https://', '')
            provider_arn = f"arn:aws:iam::{account_id}:oidc-provider/{oidc_host}"

            iam.delete_open_id_connect_provider(OpenIDConnectProviderArn=provider_arn)
            return {"deleted": provider_arn}
        except Exception as e:
            return {"skipped": str(e)}

    # ── Redis ────────────────────────────────────────────────────────

    def _cleanup_redis_keys(self, cluster_id: str):
        """
        Delete ALL Redis keys associated with this cluster.
        Every key pattern from APPENDIX A of logic.md that uses cluster_id.
        """
        patterns = [
            f"spot:cooldown:cluster:{cluster_id}",
            f"spot:cooldown:resize:{cluster_id}",
            f"spot:cooldown:pool_switch:{cluster_id}",
            f"spot:cooldown:substitute:{cluster_id}",
            f"spot:stabilization_lock:{cluster_id}",
            f"spot:node_classification:{cluster_id}",
            f"spot:cluster_mode:{cluster_id}",
            f"spot:ondemand_fallback:{cluster_id}",
            f"spot:execution_failures:{cluster_id}",
            f"spot:cluster_state:{cluster_id}",
            f"spot:execution_plan:{cluster_id}",
            f"spot:rejection_counter:{cluster_id}:*",
            f"spot:substitute:state:{cluster_id}",
            f"spot:substitute:meta:{cluster_id}",
            f"obs:decisions:{cluster_id}",
            f"cb:state:{cluster_id}",
            f"cb:rollbacks:{cluster_id}",
            f"cb:last_failure:{cluster_id}",
            f"cb:state_entered:{cluster_id}",
            f"resize:guard:{cluster_id}:invocations",
            f"resize:rollback_needed:{cluster_id}",
            f"resize:failure_count_24h:{cluster_id}",
            f"hibernation:lock:*:{cluster_id}",
        ]
        deleted = 0
        for pattern in patterns:
            if '*' in pattern:
                keys = redis_client.keys(pattern)
                if keys:
                    redis_client.delete(*keys)
                    deleted += len(keys)
            else:
                if redis_client.exists(pattern):
                    redis_client.delete(pattern)
                    deleted += 1
        return {"deleted_keys": deleted}

Bug C-4 — STS Session Not Cached (Causes the Delay from Your Bug Report)
From the bug report: Every action call hits _get_account_session() which does a live sts.assume_role() — adding 2-5 seconds of latency before anything happens.
Fix — cache STS session tokens in Redis (they are valid for 1 hour):
python# In hygiene_service.py _get_account_session() — add Redis caching:
def _get_account_session(self, account_id: str, role_arn: str, external_id: str):
    cache_key = f"sts:session:{account_id}"
    cached = redis_client.get(cache_key)
    if cached:
        creds = json.loads(cached)
        # Check not expiring in next 5 min
        expiry = datetime.fromisoformat(creds['Expiration'])
        if expiry > datetime.utcnow() + timedelta(minutes=5):
            return boto3.Session(
                aws_access_key_id=creds['AccessKeyId'],
                aws_secret_access_key=creds['SecretAccessKey'],
                aws_session_token=creds['SessionToken'],
            )

    # Cache miss — assume role
    sts = boto3.client('sts')
    response = sts.assume_role(
        RoleArn=role_arn,
        RoleSessionName=f"SpotOptimizer-{account_id}",
        ExternalId=external_id,
        DurationSeconds=3600,
    )
    creds = response['Credentials']
    creds['Expiration'] = creds['Expiration'].isoformat()

    # Cache for 55 minutes (token valid for 60 min)
    redis_client.setex(cache_key, 3300, json.dumps(creds))

    return boto3.Session(
        aws_access_key_id=creds['AccessKeyId'],
        aws_secret_access_key=creds['SecretAccessKey'],
        aws_session_token=creds['SessionToken'],
    )
