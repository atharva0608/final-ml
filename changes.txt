### 🛠️ Step 1: Fix "Discovery & Insights" (The Missing Permissions)

**Problem:** Your `backend/templates/aws/full-access-role.yaml` file is **empty**. When a client links their AWS account, they are creating a useless role.
**Goal:** Give the role permission to "See" clusters (Discovery) and "Read Costs" (Insights).

**Action:** Open `backend/templates/aws/full-access-role.yaml` and paste this content:

```yaml
AWSTemplateFormatVersion: '2010-09-09'
Description: 'Spot Optimizer Cross-Account Access Role'
Parameters:
  ExternalId:
    Type: String
    Description: 'The unique External ID provided by Spot Optimizer'
  PrincipalArn:
    Type: String
    Description: 'The ARN of your Backend Role (that will assume this role)'

Resources:
  SpotOptimizerRole:
    Type: 'AWS::IAM::Role'
    Properties:
      RoleName: !Sub 'SpotOptimizer-Access-${AWS::Region}'
      AssumeRolePolicyDocument:
        Version: '2012-10-17'
        Statement:
          - Effect: Allow
            Principal:
              AWS: !Ref PrincipalArn
            Action: 'sts:AssumeRole'
            Condition:
              StringEquals:
                'sts:ExternalId': !Ref ExternalId
      Policies:
        - PolicyName: 'SpotOptimizerDiscovery'
          PolicyDocument:
            Version: '2012-10-17'
            Statement:
              - Effect: Allow
                Action:
                  - 'eks:ListClusters'
                  - 'eks:DescribeCluster'
                  - 'eks:ListNodegroups'
                  - 'ec2:DescribeInstances'
                  - 'autoscaling:DescribeAutoScalingGroups'
                  # 💰 Cost Insights Permissions:
                  - 'ce:GetCostAndUsage'
                  - 'ce:GetCostForecast'
                Resource: '*'
        - PolicyName: 'SpotOptimizerInjection'
          PolicyDocument:
            Version: '2012-10-17'
            Statement:
              - Effect: Allow
                Action:
                  # 💉 Injection Permissions:
                  - 'eks:CreateAccessEntry'
                  - 'eks:DeleteAccessEntry'
                  - 'eks:ListAccessEntries'
                  - 'eks:AssociateAccessPolicy'
                Resource: '*'
Outputs:
  RoleArn:
    Value: !GetAtt SpotOptimizerRole.Arn

```

### 🤖 Step 2: Switch Agent to "DaemonSet" (Like CAST.AI)

**Problem:** Your `charts/.../templates/deployment.yaml` is **empty**, and you requested a DaemonSet. A DaemonSet runs one agent pod on **every node**, which is required for accurate node bin-packing and instant decision making.

**Action 1: Delete the Deployment File**
Delete `charts/spot-optimizer-agent/templates/deployment.yaml`.

**Action 2: Create a DaemonSet File**
Create `charts/spot-optimizer-agent/templates/daemonset.yaml` with this content:

```yaml
apiVersion: apps/v1
kind: DaemonSet  # <--- Changed from Deployment
metadata:
  name: spot-agent
  namespace: {{ .Values.namespace }}
  labels:
    app: spot-agent
spec:
  selector:
    matchLabels:
      app: spot-agent
  template:
    metadata:
      labels:
        app: spot-agent
    spec:
      serviceAccountName: spot-agent-sa
      # Host Network is often needed for deep node monitoring, 
      # but standard mode is safer to start.
      hostNetwork: false 
      containers:
        - name: agent
          image: "{{ .Values.image.repository }}:{{ .Values.image.tag }}"
          imagePullPolicy: Always
          env:
            - name: NODE_NAME
              valueFrom:
                fieldRef:
                  fieldPath: spec.nodeName
            - name: API_KEY
              valueFrom:
                secretKeyRef:
                  name: spot-agent-secret
                  key: API_KEY
            - name: BACKEND_URL
              valueFrom:
                configMapKeyRef:
                  name: spot-agent-config
                  key: BACKEND_URL
            - name: CLUSTER_ID
              valueFrom:
                configMapKeyRef:
                  name: spot-agent-config
                  key: CLUSTER_ID
          resources:
            requests:
              cpu: 100m
              memory: 128Mi
            limits:
              cpu: 500m
              memory: 512Mi

```
