### 💉 Part 2: Fix Agent Injection (The "Operation")

*The injection is crashing because the Backend is trying to send a "Certificate String" where the code expects a "File Path".*

**1. Fix the SSL Error (`agent_injector.py`)**

* **Problem:** The error `[X509: NO_CERTIFICATE_OR_CRL_FOUND]` happens because the AWS API gives you a certificate as text, but the Kubernetes Client demands a file on the disk.
* **Action:** In `backend/services/agent_injector.py` (inside the `_deploy_agent` function), you must add logic to:
1. Create a **Temporary Named File** (using python `tempfile` module).
2. Write the decoded certificate data to this file.
3. Pass the **Path** of this temporary file to `configuration.ssl_ca_cert`.
4. *Logic:* `with tempfile.NamedTemporaryFile(delete=False) as cert_file: ...`



**2. Fix the Region Crash (`agent_injector.py`)**

* **Problem:** `botocore.exceptions.NoRegionError`.
* **Action:** In the same file, find where you create the AWS client: `boto3.client('sts')`.
* **Fix:** You **must** change it to `boto3.client('sts', region_name=cluster.region)`.

### 🔴 Severity: High (Security & Stability Risks)

#### 1. The "Synchronous Injection" Timeout Risk

* **Location:** `backend/api/cluster_routes.py` calling `agent_injector.py`
* **The Problem:** Your logs show the injection request took **~8.9 seconds**.
* API Gateways (like Nginx, AWS ALB) often timeout at 30-60s.
* If AWS is slow (e.g., creating the `AccessEntry` takes 45s), the Frontend will receive a **504 Gateway Timeout**.
* The user will click "Connect" again, triggering a **duplicate injection**, potentially corrupting the state.


* **The Fix:** Move `agent_injector.inject_agent` to a **Celery Background Task**. The API should return `202 Accepted` immediately, and the Frontend should poll the status.

#### 2. The "Confused Deputy" Security Hole

* **Location:** `backend/templates/aws/full-access-role.yaml`
* **The Problem:** Your IAM Trust Policy likely allows `Principal: AWS: <Your_Backend_ARN>`.
* Without an **External ID**, if a hacker knows your Backend ARN, they could theoretically create a role in *their* account pointing to *your* backend, confusing your system into managing their infrastructure (or vice-versa in complex scenarios).


* **The Fix:** Enforce `sts:ExternalId` in the Trust Relationship. Your backend must generate a unique UUID for every Organization and require the customer to use it during stack creation.

#### 3. The "Latest Tag" Timebomb

* **Location:** `charts/spot-optimizer-agent/templates/daemonset.yaml` (and `install.sh`)
* **The Problem:** You are using `image: atharva0608/spot-optimizer-agent:latest`.
* **Scenario:** You push a new version of the agent on Friday night that has a small bug.
* **Result:** **Every single client cluster** (hundreds of them) will pull the broken image immediately upon restart or scaling. Your entire customer base goes down at once.


* **The Fix:** ALWAYS pin versions (e.g., `v1.2.0`). The backend should control when to upgrade specific customers.

### 🟠 Severity: Medium (Logic & Cost Risks)

#### 4. The "Cost Explorer" Billing Spike

* **Location:** `backend/workers/tasks/discovery.py`
* **The Problem:** AWS charges **$0.01 per request** for the Cost Explorer API.
* If your discovery runs every **5 minutes** and loops through **10 regions** for **10 clients**:
* `10 clients * 10 regions * 12 runs/hour * 24 hours * 30 days` = ~86,400 requests.
* **Bill:** ~$864/month just for you to *check* if costs changed.


* **The Fix:**
1. Cache Cost Data in Redis for 4-24 hours.
2. Only call Cost Explorer once per day (Cost Explorer data is only updated daily anyway; calling it every 5 mins is useless).



#### 5. Missing Pagination (The "100 Cluster" Limit)

* **Location:** `backend/workers/tasks/discovery.py`
* **The Problem:** `eks_client.list_clusters()` returns a maximum of **100** clusters by default. If a large enterprise client connects an account with 105 clusters, the last 5 will remain invisible forever because your code likely doesn't check `NextToken`.
* **The Fix:** Wrap boto3 calls in a `paginator` loop.

#### 6. The "Missing Metrics" Gap

* **Location:** `agent/collector.py`
* **The Problem:** The k8s Python client used in the agent grabs *logical* data (Deployment specs, Pod status). It does **not** natively grab *OS-level* metrics (Real CPU Usage %, Memory Pressure) without the **Metrics Server** being installed in the cluster.
* **The Fix:**
* Your installer must check if `metrics-server` exists.
* If not, your agent must install it, or your agent must read from `/proc/stat` directly (since you have `hostNetwork: true` and are a DaemonSet).

### 🟡 Severity: Low (User Experience)

#### 7. Hardcoded "US-EAST-1" Bias

* **Location:** `backend/services/agent_injector.py` (potentially)

#### 8. Docker "Root" User

* **Location:** `agent/Dockerfile`
* **The Problem:** Running the agent as `root` inside the container is a security best-practice violation. Many enterprise OPA (Open Policy Agent) Gatekeepers will **block** your agent installation because it doesn't specify a `USER 1000`.
* **The Fix:** Add `USER nonroot` in Dockerfile and `securityContext` in `daemonset.yaml`.
