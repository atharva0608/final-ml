Here are the **Functional Specifications** and **Implementation Guidelines** to introduce the **Super Admin (Platform Admin)** role. This role is strictly separated from Client Data operations.

### 1. The Core Principle: "Platform vs. Tenant" Separation

You must architecturally enforce that the **Super Admin** manages the *Container*, while the **Organization Admin** manages the *Content*.

* **Super Admin Scope:** The Application Infrastructure (Database health, ML Models, Global Pricing Config, Tenant Billing Status).
* **Organization Admin Scope:** The Client Cloud Resources (AWS Accounts, EC2 Instances, Team Members, Cost Savings).

### 2. Permission Constraints (The "Iron Wall")

To ensure the Super Admin cannot touch client accounts, implement these logic rules in your **Authorization Middleware**:

#### **A. Explicit Deny on Resource Actions**

* **The Rule:** Any API endpoint that interacts with a cloud provider (AWS/GCP/Azure) or modifies specific client resources must **Block** the Super Admin role.
* **Affected Actions:** `Terminate Instance`, `Delete Volume`, `Connect Cloud Account`, `Scan Infrastructure`, `Execute Cleanup`.
* **Implementation Note:** In your permission checker, if `user.role == 'SUPER_ADMIN'`, these endpoints should return `403 Forbidden` with a message: *"Platform Admins cannot modify client resources."*

#### **B. Read-Only "Shadow" View (Optional but Restricted)**

* If you allow Super Admins to *see* client data for support purposes, it must be strictly **Read-Only**.
* **Masking:** Sensitive data like AWS Access Keys, Cost details, or PII must be masked even for the Super Admin.

---

### 3. Super Admin Capabilities (What they CAN do)

The Super Admin dashboard should look completely different from the Client dashboard. It focuses on **System Health** and **Tenant Governance**.

#### **Feature 1: Tenant & License Management**

* **Organization Oversight:** A list of all registered clients (Organizations).
* **Actions:**
* **Onboard/Offboard:** Create new client environments or suspend non-paying clients.
* **Feature Toggles:** Enable/Disable specific modules per client (e.g., "Grant Client A access to *Spot Instance Optimization* feature").
* **Limit Configuration:** Set limits on how many team members or AWS accounts a client can add.



#### **Feature 2: ML Model Governance**

* **Centralized Model Registry:** The Super Admin manages the AI/ML models used by the optimization engine.
* **Actions:**
* **Push Updates:** Upload a new version of the "Rightsizing Algorithm" that applies to all clients.
* **Model Config:** Tweak global hyperparameters (e.g., "Aggressiveness of savings recommendations") without touching client data directly.



#### **Feature 3: System Performance & Health**

* **Application Metrics:** View the CPU, Memory, and Latency of the *SaaS Platform itself* (not the client's servers).
* **Job Queues:** Monitor the status of background workers (e.g., "10,000 optimization jobs pending").
* **Global Audit:** A master log showing *which* Organization Admin did what, for compliance and platform security.

---

### 4. Dashboard UX: The "God View"

#### **Navigation Menu**

Remove all "Resource" tabs. Replace them with:

1. **Tenants:** (List of Organizations, Subscription Status, Active Users).
2. **Platform Health:** (Redis Status, API Latency, Error Rates).
3. **Model Registry:** (Manage ML versions).
4. **Global Config:** (Pricing APIs, System Maintenance Mode).

#### **The "Impersonation" Risk**

* **Decision:** You must decide if a Super Admin can "Log in as Client".
* **Recommendation:** **Disable this by default.** If implemented for support, it requires a "Break Glass" procedure that logs a critical alert and notifies the Client Org Admin immediately.

### Summary of Hierarchical Access

| Action | Super Admin (Platform) | Org Admin (Client) |
| --- | --- | --- |
| **Update App Version** | ✅ **Yes** | ❌ No |
| **Disable Client Org** | ✅ **Yes** | ❌ No |
| **Update Billing Plan** | ✅ **Yes** | ❌ No |
| **Delete Client EC2** | ❌ **BLOCK** | ✅ **Yes** |
| **Add AWS Account** | ❌ **BLOCK** | ✅ **Yes** |
| **Invite Team Member** | ❌ **BLOCK** | ✅ **Yes** |
