Here are the detailed, non-code functional instructions for implementing the **Tag Management System**. These instructions act as a blueprint for the frontend and product teams, detailing every popup, button, and user interaction required.

### 1. Admin Interface: Tag Policy Management

**Location:** `Settings` > `Governance` > `Tag Policies` (New Tab)

**A. The "Tag Policies" List View**

* **Display:** Create a table listing all active tag policies.
* **Columns:**
* **Tag Key:** (e.g., "Owner", "CostCenter")
* **Enforcement:** Badge showing "Advisory" (Yellow), "Required" (Red), or "Strict" (Black).
* **Scope:** Icons representing resource types (EC2, S3, RDS).
* **Compliance:** A progress bar showing % of resources that currently have this tag.
* **Actions:** "Edit" (Pencil icon) and "Delete" (Trash icon) buttons.


* **Primary Action:** Add a prominent **"Create Tag Policy"** button at the top right.

**B. The "Create/Edit Policy" Modal**

* **Trigger:** Clicking "Create Tag Policy" or "Edit".
* **Header:** "Configure Tag Governance".
* **Form Fields:**
1. **Tag Key (Input):** The exact name of the tag (e.g., `Environment`).
2. **Description (Text Area):** Help text for users (e.g., "Defines the deployment stage").
3. **Allowed Values (Dynamic List):**
* Radio toggle: "Free Text" vs. "Pre-defined List".
* If "List": Show an input field with an "Add" button to build a list of valid options (e.g., `Prod`, `Dev`, `Staging`).


4. **Validation (Input):** Optional Regex field (e.g., `^CC-\d{4}$`) for format checking.
5. **Enforcement Level (Dropdown):** Options: `Advisory` (Warning only), `Required` (Blocks cleanup actions).


* **Footer Actions:** "Cancel" and "Save Policy".

---

### 2. Resource Table Enhancements

**Location:** `Cleanup Dashboard` (Compute, Storage, etc.)

**A. The "Tags" Column Redesign**

* **Current State:** Replace the simple badge (e.g., "3 Tags").
* **New Visual State:**
* **Compliant:** Show a **Green Checkmark** if all "Required" policies are met.
* **Non-Compliant:** Show a **Red Warning Icon** with a count of missing required tags (e.g., "⚠ Missing: Owner").
* **Hover Interaction:**
* Hovering over the icon must trigger a **Tooltip**.
* Tooltip content: A mini-list of all current tags on that resource (`Key: Value`).




* **Click Interaction:** Clicking anywhere in the "Tags" cell must open the **Inline Tag Editor Modal**.

**B. Selection & Bulk Actions**

* **Trigger:** User checks the checkboxes next to multiple resources.
* **Floating Action Bar:** When items are selected, show a floating bar at the bottom or top of the table.
* **Action Button:** Add a button labeled **"Tag Selected Resources (X)"**.
* **Click Interaction:** Opens the **Bulk Tagging Modal**.

---

### 3. The "Inline Tag Editor" Popup

**Trigger:** Clicking the "Tags" column of a specific resource.

**A. Modal Layout**

* **Title:** "Edit Tags for [Resource ID]" (e.g., `vol-0x123...`).
* **Section 1: Required Tags (The Compliance Check)**
* Display a list of all "Required" tag keys defined in Admin settings.
* **Visual Cue:** If a required tag is missing, highlight the input field in **Red**.
* **Input Type:**
* If the policy has "Allowed Values," render a **Dropdown**.
* If the policy is "Free Text," render a **Text Input**.




* **Section 2: Optional Tags**
* Display existing AWS tags that are not in the "Required" list.
* Action: **"+ Add New Tag"** link to add a blank row (Key/Value inputs).


* **Section 3: Smart Suggestions (AI)**
* Display a "Suggested Tags" panel if the system detects patterns.
* *Example:* "We detected 'Environment: Prod' based on the resource name."
* Action: **"Accept"** button next to the suggestion to auto-fill the field.



**B. Footer Actions**

* **"Propagate to Related":** A checkbox option: "Also apply these tags to attached Snapshots/Volumes".
* **Buttons:** "Cancel" and **"Save Changes"**.
* **Submission Logic:** On Save, show a loading spinner, send API request to AWS, then refresh the row's compliance icon immediately.

---

### 4. The "Bulk Tagging" Interface

**Trigger:** Clicking "Tag Selected Resources" from the table.

**A. Modal Layout**

* **Title:** "Bulk Tagging [X] Resources".
* **Operation Mode Toggle:**
* **"Update/Merge":** Adds new tags or updates existing ones (leaves others alone).
* **"Replace All":** Wipes all existing tags and sets only the new ones (Show a warning alert if selected).


* **The Tagging Form:**
* Standard "Key" and "Value" input pairs.
* **"Apply Template" Dropdown:** Allow selecting a preset (e.g., "Cost Center Standard") which pre-fills the rows.


* **Preview Section:**
* Show a summary: "This will apply 'Owner: Alice' to 45 volumes."
* **Conflict Warning:** If selected resources have *different* existing values for a tag, show a warning: "Mixed values detected for 'Owner'. This action will overwrite them all to 'Alice'."



**B. Footer Actions**

* **Buttons:** "Cancel" and **"Apply Tags"**.
* **Feedback:** Upon completion, show a "Toast" notification: "Successfully tagged 45 resources."

---

### 5. Automation: Auto-Tagging Rules (Future Phase)

**Location:** `Settings` > `Governance` > `Automation`

**A. "Create Auto-Tag Rule" Workflow**

* **Step 1: Scope Definition**
* Dropdowns to select: "Region" (e.g., us-east-1), "Resource Type" (e.g., EC2).
* **Name Pattern Input:** "If Resource Name contains..." (e.g., `prod-`).


* **Step 2: Tag Definition**
* Define the tag to apply automatically (e.g., Key: `Environment`, Value: `Production`).


* **Step 3: Review**
* **"Test Rule" Button:** clearly display "This rule would currently match 14 resources."


* **Step 4: Save**
* Option to "Run Now" (Retroactive) or "Active for Future" (New resources only).



### Summary of Critical UX Flows

1. **The "Fix-It" Loop:** User sees Red Icon  Clicks Icon  Pop-up shows missing field in Red  User fills it  Clicks Save  Icon turns Green.
2. **The "Governance" Setup:** Admin defines "Owner" is required  All existing resources without "Owner" instantly turn Red in the dashboard.
