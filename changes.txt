Here are the detailed **Non-Code Functional Instructions** to implement the "Authorization Gate" and "Template-Based Bulk Tagging" systems.

These instructions map directly to the **Resource Hygiene** and **Governance** modules of your application.

---

### 1. The "Authorization Gate" Workflow (Strict Enforcement)

This feature modifies the **Onboarding/Discovery** process. It prevents "dirty" (untagged) resources from entering the "managed" state unless specific criteria are met.

#### **A. The "Discovered Resources" Table Logic**

**Location:** `Resource Hygiene` > `Discovered Assets` (or `Onboarding` tab).

1. **New Column: "Compliance Status"**
* Add a column next to the resource name/ID.
* **Logic:** For every row, the frontend checks the resource's current tags against the **Active Tag Policies** (fetched from Settings).
* **Visual States:**
* 🟢 **Ready:** All "Required" tags are present and valid.
* 🔴 **Violation:** One or more "Required" tags are missing or invalid.




2. **The "Authorize" Button Behavior (Role-Dependent)**
* **Scenario:** A resource has a 🔴 **Violation** status.
* **If User is MEMBER or TEAM_LEAD:**
* **Button State:** **Disabled (Greyed out).**
* **Tooltip:** Hovering over the button displays: *"Mandatory tags missing. You must fix tags before authorizing."*
* **Required Action:** The user *must* click the **"Edit Tags"** icon in the row, add the required tags, save, and wait for the status to turn 🟢 before they can click Authorize.


* **If User is ORG_ADMIN:**
* **Button State:** **Enabled.**
* **Action:** Clicking "Authorize" triggers a **Override Warning Modal**.
* **Modal Content:** *"This resource violates tag policies (Missing: CostCenter). Authorizing it now will lower your compliance score. Do you want to proceed?"*
* **Buttons:** [Cancel] [**Force Authorize**] (Logs the bypass in Audit Logs).





#### **B. Backend Enforcement (Safety Net)**

* **Endpoint:** `POST /api/onboarding/authorize`
* **Logic Update:**
* If `user.role != ORG_ADMIN`, the backend validates the tags again.
* If validation fails, return `400 Bad Request` with message: *"Tag policy violation. Authorization denied."*
* This prevents users from bypassing the UI via API calls.

### 2. Feature: Tag Template Management

**Location:** `Settings` > `Governance` > `Tag Templates` (New Tab).

**Goal:** Allow users to define standard sets of tags (presets) to apply quickly later.

#### **A. The "Create Template" Workflow**

1. **Button:** "Create New Template".
2. **The Form:**
* **Template Name:** (e.g., "Production Standard", "Dev Team Alpha").
* **Resource Scope:** Dropdown to select if this applies to `All Resources`, `EC2 Only`, `S3 Only`, etc.
* **Tag Builder:** A dynamic list of Key-Value pairs.
* *Row 1:* `Environment` = `Production`
* *Row 2:* `CostCenter` = `CC-Fin-01`
* *Row 3:* `CreatedBy` = `{CURRENT_USER_EMAIL}` (Dynamic Variable).




3. **Validation:**
* If a user adds a tag key that contradicts a "Strict Policy" (e.g., enters an invalid CostCenter format), show an error immediately: *"Value does not match the Regex required for CostCenter."*



#### **B. Visibility Scope**

* **ORG_ADMIN templates:** Visible to the **Entire Organization**.
* **TEAM_LEAD templates:** Visible only to their **Specific Team**.

### 3. Feature: Bulk Tagging Wizard

**Location:** `Resource Hygiene` > `Tag Management` (or any Resource Table).

**Goal:** Apply templates to hundreds of resources in 3 clicks.

#### **Step 1: Selection & Filter**

* Add a **"Resource Class" Filter** at the top (e.g., "Show: EC2 Instances", "Show: S3 Buckets").
* User selects 10, 50, or "Select All" rows.
* **Action:** Click the **"Bulk Tag"** button in the floating action bar.

#### **Step 2: The Wizard Modal**

* **Title:** "Tagging 24 Selected Resources".
* **Tab 1: Use Template (Default)**
* **Dropdown:** Select a template (e.g., "Dev Team Alpha").
* **Preview:** Shows the list of tags that will be applied.
* **"Variable Input":** If the template has a variable (like `{ProjectID}`), ask the user to input the value *once* here.


* **Tab 2: Manual Entry**
* Add Key/Value pairs manually for ad-hoc tagging.



#### **Step 3: Collision Handling (Crucial)**

* **Question:** *"Some resources already have these tags. What should we do?"*
* **Radio Options:**
* ⚪ **Skip Existing:** If `Environment` tag exists, do not change it. Only add missing tags.
* 🔘 **Overwrite (Force):** Update all selected resources to match this template exactly.



#### **Step 4: Execution**

* Show a progress bar: *"Updating 14/24 resources..."*
* **Result:** *"Success: 22 Updated. 2 Failed (Insufficient Permissions)."*

### 4. Advanced "Smart Tags" Logic

These are backend logic rules that look for *specific* tags to perform automated actions.

#### **A. The "TTL" (Time-To-Live) Tag**

* **Tag Key:** `auto:termination_date`
* **Value Format:** `YYYY-MM-DD` (e.g., `2026-12-31`).
* **Logic:**
* Create a daily background job (Cron).
* Scan all resources with this tag.
* **Check:** `IF Today > Tag_Value`.
* **Action:**
1. **Mark as "Expired"** in the Resource Hygiene Dashboard (High Severity).
2. Send an email/Slack alert to the resource owner: *"Your instance expired yesterday."*
3. (Optional Config) **Stop** the instance.





#### **B. The "Scheduler" Tag**

* **Tag Key:** `auto:schedule`
* **Value Enum:** `Weekdays-Only`, `Office-Hours`, `Always-On`.
* **Logic:**
* Integrate with your **Hibernation Service**.
* Instead of manually assigning schedules in the UI, the Hibernation Service simply reads this tag.
* *Example:* If tag is `Weekdays-Only` and today is Sunday  **Stop Instance**.



#### **C. The "Budget Scope" Tag**

* **Tag Key:** `finance:budget_code`
* **Logic:**
* In the **Billing Dashboard**, add a "Group By" dropdown.
* Select "Budget Code".
* The system aggregates costs based purely on this tag.
* **Anomaly Detection:** Any resource *missing* this tag is grouped into a red bucket labeled **"Unallocated Spend"** to prompt immediate fixing.
