# Hibernation Schedules - Complete Feature Specification

## 🎯 Core Concept

**Hibernation = Automatically sleep clusters during non-business hours to save costs**

Think of it like an **automated thermostat** for your Kubernetes infrastructure.

---

## 📋 What Should Be Included

### **1. Schedule Management**

#### A. Create/Edit Schedule
```
User configures:
├─ Schedule Name (e.g., "Weekend Shutdown")
├─ Hibernation Strategy (3 types - see below)
├─ Target Clusters (multi-select)
├─ Sleep Days (Mon, Tue, Wed, Thu, Fri, Sat, Sun)
├─ Sleep Window (Start time → End time)
├─ Timezone (UTC, PST, EST, etc.)
├─ Pre-warm Duration (0-60 minutes)
└─ Activation Status (Active/Paused)
```

#### B. Hibernation Strategies (3 Types)

```jsx
┌─────────────────────────────────────────────────────────────────┐
│  SELECT HIBERNATION STRATEGY                                    │
├─────────────────────────────────────────────────────────────────┤
│                                                                  │
│  ┌─────────────────────────────────────────────────────────┐   │
│  │ 🌙 NAMESPACE SLEEP (Recommended)                        │   │
│  │                                                          │   │
│  │ What it does:                                           │   │
│  │ • Scales all workload replicas to 0                    │   │
│  │ • Keeps nodes and control plane running                │   │
│  │ • Fastest wake time (~2 minutes)                       │   │
│  │                                                          │   │
│  │ Best for:                                               │   │
│  │ ✅ Development/staging environments                     │   │
│  │ ✅ Stateless applications                               │   │
│  │ ✅ Frequent wake cycles                                 │   │
│  │                                                          │   │
│  │ Savings: ~80%  |  Wake: 2min  |  Risk: Low             │   │
│  └─────────────────────────────────────────────────────────┘   │
│                                                                  │
│  ┌─────────────────────────────────────────────────────────┐   │
│  │ 🖥️ NODE SCALE-DOWN (Balanced)                          │   │
│  │                                                          │   │
│  │ What it does:                                           │   │
│  │ • Terminates worker nodes                              │   │
│  │ • Keeps control plane active                           │   │
│  │ • Medium wake time (~5 minutes)                        │   │
│  │                                                          │   │
│  │ Best for:                                               │   │
│  │ ✅ Cost-sensitive non-prod clusters                     │   │
│  │ ✅ Clusters with auto-scaling                           │   │
│  │ ✅ Overnight/weekend hibernation                        │   │
│  │                                                          │   │
│  │ Savings: ~70%  |  Wake: 5min  |  Risk: Medium          │   │
│  └─────────────────────────────────────────────────────────┘   │
│                                                                  │
│  ┌─────────────────────────────────────────────────────────┐   │
│  │ 💥 FULL HIBERNATION - NUCLEAR (Maximum Savings)        │   │
│  │                                                          │   │
│  │ What it does:                                           │   │
│  │ • Stops entire cluster (control + worker nodes)        │   │
│  │ • EBS volumes retained                                 │   │
│  │ • Longest wake time (~15 minutes)                      │   │
│  │                                                          │   │
│  │ Best for:                                               │   │
│  │ ⚠️ POC/demo environments                                │   │
│  │ ⚠️ Long-duration hibernation (weekends/holidays)       │   │
│  │ ⚠️ Non-critical workloads only                          │   │
│  │                                                          │   │
│  │ Savings: ~95%  |  Wake: 15min  |  Risk: High           │   │
│  └─────────────────────────────────────────────────────────┘   │
│                                                                  │
└─────────────────────────────────────────────────────────────────┘
```

## 🔧 Technical Implementation Details

### **Backend Jobs (Celery/Cron)**

```python
# Scheduled task runs every 1 minute
@celery.task
def execute_hibernation_scheduler():
    """
    Check if any schedules should trigger now
    """
    now = datetime.utcnow()
    
    # Find schedules that should trigger
    schedules = db.query(HibernationSchedule).filter(
        HibernationSchedule.is_active == True,
        HibernationSchedule.next_execution <= now
    ).all()
    
    for schedule in schedules:
        # Determine action (sleep or wake)
        action = determine_action(schedule, now)
        
        if action == "sleep":
            execute_hibernation.delay(schedule.id)
        elif action == "wake":
            execute_wake.delay(schedule.id)
        
        # Update next_execution
        schedule.next_execution = calculate_next_execution(schedule)
        db.commit()
```

### **State Machine**

```
Schedule States:
├─ DRAFT (not activated yet)
├─ ACTIVE (running on schedule)
├─ PAUSED (temporarily disabled)
├─ EXECUTING (currently hibernating/waking)
├─ ERROR (last execution failed)
└─ ARCHIVED (deleted but kept for history)

Execution States:
├─ PENDING (waiting for execution time)
├─ PRE_WARMING (starting nodes early)
├─ SLEEPING (scaling down)
├─ HIBERNATED (fully asleep)
├─ WAKING (scaling up)
├─ AWAKE (fully running)
└─ FAILED (error during execution)
```
