# Resource Hygiene Dashboard - Professional UX/UI Specification

## Core Philosophy
Create an **enterprise-grade analytics and optimization platform** that transforms cloud waste detection from reactive cleanup into proactive cost governance. The interface should function as a decision-support system that combines data visualization, dependency analysis, and guided workflows.

---

## **SECTION 1: Dashboard Landing - Intelligence Overview**

### Hero Metrics Panel (Full Width, 4 Equal Columns)

#### Column 1: Total Waste Summary
- **Large numeral display**: Total monthly waste across all categories
  - Animated count-up on load
  - Comparison indicator: "↑ $450 vs last scan" or "↓ 12% from last week"
  - Percentage of total AWS spend shown below in smaller text
- **Mini trend sparkline**: Last 10 scans showing waste trajectory
  - Subtle line chart, no axes, just the pattern
  - Click to expand into detailed trend modal

#### Column 2: Resource Distribution
- **Donut chart**: Resources by category
  - Segments: Compute (red tones), Storage (blue tones), Network (green tones), Database (purple tones), Identity (orange tones)
  - Center displays total resource count flagged
  - Interactive: Hover shows exact count + percentage
  - Click segment to filter entire dashboard to that category
- **Legend below**: Icon + Label + Count for each segment

#### Column 3: Compliance Health
- **Semi-circular gauge chart**: Tag compliance percentage
  - Needle points to current compliance score
  - Color zones: 0-50% (warning), 50-80% (caution), 80-100% (healthy)
  - Center text: "X resources untagged"
- **Breakdown bar** beneath gauge:
  - Horizontal stacked bar showing compliant (green) vs non-compliant (red) ratio
  - Exact counts on hover

#### Column 4: Safety Assessment
- **Three-tier safety distribution**:
  - Horizontal bar chart with 3 bars stacked:
    - Safe to Delete (green bar)
    - Needs Review (yellow bar)
    - Risky/Has Dependencies (red bar)
  - Each bar shows count and percentage
  - Click bar to filter table to that safety level
- **Quick Action Recommendation**: 
  - Text: "XX resources ready for immediate cleanup"
  - Button: "Review Safe Items"

**Two-Row Filter Layout:**

#### Row 1: Scope Filters
- **Account Selector**: Dropdown with multi-select capability
  - Shows account name + AWS account ID
  - "Select All" option
  - Selected count badge
- **Region Multi-Select**: 
  - Chip-based selection (click to toggle)
  - "All Regions" quick toggle
  - Visual map thumbnail showing selected regions highlighted
- **Date Range**: Scan history selector
  - Quick picks: "Latest", "Last 7 days", "Last 30 days"

#### Row 2: Attribute Filters
- **Safety Level**: Three toggle buttons (Safe / Review / Risky)
  - Multiple can be active simultaneously
  - Show counts for each level
- **Compliance Status**: Two toggle buttons (Compliant / Non-Compliant)
- **Cost Range**: Dual-handle slider
  - Min/Max inputs for precise values
  - Histogram background showing cost distribution
- **Age Range**: Slider for resource age (0-365+ days)

**Active Filter Summary Bar:**
- Displays active filters as dismissible pills
- "Clear All" link
- "Save Filter Preset" option for frequently used combinations
- Filter count indicator

### **TAB 1-9: Existing Resource Types - Enhanced Visualizations**

#### Compute Tab (Unauthorized Instances)
**Summary Cards:**
1. Total unauthorized instances running
2. Daily waste cost (instances × hourly rate × 24)
3. Average instance age

**Visualization: Regional Heat Map Matrix**
- Rows: Instance types (t3.micro, m5.large, etc.)
- Columns: Regions
- Cell color intensity: Number of unauthorized instances
- Cell value: Count + monthly cost
- Click cell: Filters table to that instance type + region combination
- Tooltip on hover: Instance IDs preview

#### Storage Tab (Volumes + Snapshots)
**Summary Cards:**
1. Total orphaned storage (GB)
2. Oldest orphaned resource age
3. GP2→GP3 upgrade opportunities count

**Visualization: Age Distribution Histogram**
- X-axis: Age buckets (0-30d, 31-60d, 61-90d, 91-180d, 181-365d, 365d+)
- Y-axis: Count of resources
- Stacked bars: Volumes (bottom) + Snapshots (top) in different shades
- Second Y-axis: Cumulative cost curve overlaid
- Click bar: Filters table to that age range
- Special highlight: Resources >90 days (recommended cleanup threshold)

#### Network Tab (EIPs, LBs, ENIs)
**Summary Cards:**
1. Unused Elastic IPs count + monthly cost
2. Idle load balancers (0 targets)
3. Unattached network interfaces

**Visualization: Sankey Flow Diagram**
- Left side: Resource categories (EIPs, LBs, ENIs)
- Middle: State (Active, Idle, Unattached)
- Right side: Cost impact (High, Medium, Low)
- Flow width: Proportional to resource count
- Color coding by cost severity
- Click flow path: Filters to that combination

#### Database Tab (RDS)
**Summary Cards:**
1. Idle databases (0 connections in 7 days)
2. Legacy generation instances (t2, m4)
3. Multi-AZ savings opportunity preview

**Visualization: Generation Matrix**
- Table-style heat map
- Rows: Database engines (MySQL, PostgreSQL, MariaDB, Oracle, SQL Server)
- Columns: Instance generations (t2, t3, m4, m5, m6, r4, r5, r6)
- Cell shows: Instance count
- Legacy generations (t2, m4, r4) have warning border
- Color intensity: Cost impact
- Tooltip: "XX instances, upgrade to YY generation to save $ZZZ/mo"
- Click cell: Opens upgrade wizard for those instances

#### Identity Tab (IAM Users)
**Summary Cards:**
1. Dormant users (>90 days no activity)
2. Users with unused access keys
3. Total potential security risk score

**Visualization: Activity Timeline Grid**
- Rows: IAM usernames (sorted by last activity, oldest first)
- Columns: Last 90 days (each day is a thin column)
- Cell color: Activity level (dark = active, light = inactive, white = no activity)
- Pattern recognition: Easily spot users with no recent activity
- Hover: Shows exact activity details for that day
- Click row: Expands to show detailed access history

### **TAB 11: S3 Lifecycle Optimization - NEW**

#### Summary Cards
1. **Buckets Without Lifecycle Policies**: Count
2. **Storage in Wrong Tier**: TB of data in Standard that should be cheaper tier
3. **Monthly Savings Opportunity**: Projected savings from optimization

#### Primary Visualization: Storage Class Flow Diagram
**Sankey Diagram:**
- Left: S3 buckets (sized by total storage)
- Middle: Current storage classes (Standard, Standard-IA, Glacier, Deep Archive, Intelligent-Tiering)
- Right: Recommended storage classes
- Flows show where data should move
- Width = Amount of data (GB/TB)
- Color: Cost impact (green = savings, gray = already optimal)
- Click flow: Shows detailed policy recommendation

#### Secondary Visualization: Access Pattern Analysis
**Scatter Plot per Bucket:**
- X-axis: Object age (days)
- Y-axis: Access frequency (requests/day)
- Each dot = Group of objects
- Color zones:
  - Hot (frequently accessed) = Standard tier appropriate
  - Warm (occasional access) = Consider Standard-IA
  - Cold (rare access) = Move to Glacier
  - Frozen (no access >180d) = Deep Archive candidate
- Trend lines showing optimal tier boundaries
- Click zone: Generates lifecycle policy for that pattern

#### Bucket Detail Cards (Below Chart)
**Scrollable horizontal card carousel:**
Each card represents one bucket with:
- Bucket name + region
- Total size (GB) + Object count
- Current monthly cost
- **Storage Class Breakdown**: Mini donut chart showing distribution
- **Lifecycle Status**: Badge (None / Suboptimal / Optimized)
- **Recommended Action**: One-line summary
- **Projected Savings**: Dollar amount with percentage
- **Quick Apply** button: One-click policy implementation

#### Lifecycle Policy Builder (Modal)
**Visual Policy Constructor:**
- Drag-and-drop timeline interface
- Add rules: "After X days → Move to Y tier"
- Visual preview of object movement over time
- Cost impact calculator (Before/After comparison)
- Simulation mode: "What would happen if I applied this 30 days ago?"
- Export policy as JSON/Terraform

### **TAB 13: Data Transfer Optimization - NEW**

#### Summary Cards
1. **Total Monthly Transfer Cost**: Across all categories
2. **Cross-Region Traffic**: GB + cost
3. **NAT Gateway Processing**: GB + cost
4. **Top Optimization**: Biggest single opportunity

#### Primary Visualization: Traffic Flow Map
**Geographical Network Diagram:**
- Nodes: AWS regions (sized by data volume)
- Edges: Data transfer paths between regions
- Edge thickness: Proportional to GB transferred
- Edge color: Cost per GB (red = expensive internet egress, orange = cross-region, yellow = cross-AZ)
- **Annotations on edges**: "$XXX/mo" cost labels
- Click edge: Shows detailed traffic breakdown for that path
- Highlight opportunities: "Add VPC endpoint here to save $XXX"

#### Secondary Visualization: Transfer Cost Breakdown
**Treemap:**
- Top level: Transfer categories (Internet Egress, NAT Gateway, Cross-Region, Cross-AZ, VPC Peering)
- Second level: Specific source/destination pairs
- Third level: Resource types (EC2, S3, RDS, etc.)
- Size = Cost magnitude
- Color = Optimization potential (green = already optimal, yellow = minor savings, red = major savings)
- Click rectangle: Drills down or shows recommendation

#### Optimization Opportunity Cards (Below Chart)
**Prioritized list of actionable recommendations:**

Each card shows:
- **Issue Icon + Title**: "S3 Traffic via NAT Gateway"
- **Current State**: "8.2 TB/month through NAT = $369"
- **Recommended Solution**: "Create S3 VPC Endpoint"
- **Impact**: "Reduce cost to $0 (100% savings)"
- **Effort**: Badge (Low/Medium/High)
- **Implementation Time**: "5 minutes"
- **Risk**: Badge (None/Low/Medium)
- **Action Button**: "Create Endpoint" or "Learn More"

**Card Types:**
1. **CloudFront Opportunity**: Buckets serving traffic without CDN
2. **VPC Endpoint Missing**: S3/DynamoDB traffic via NAT
3. **Cross-Region Service Calls**: Apps calling services in wrong region
4. **NAT Gateway Consolidation**: Multiple NATs where one would suffice
5. **Transfer Acceleration**: Slow uploads from distant locations

## **SECTION 5: Cleanup Wizards - Step-by-Step Guided Workflows**

### **Wizard 1: Reserved Instance Optimization Wizard**

**Entry Point:** "Optimize RIs" button on RI tab

#### Step 1: Issue Identification
- **Header**: "Reserved Instance Analysis"
- **Content**: 
  - Visual summary of underutilized RIs
  - Categorized list:
    - **Critical**: 0% utilization (complete waste)
    - **Warning**: <50% utilization
    - **Monitor**: 50-70% utilization
  - Each item shows: RI ID, Type, Utilization %, Monthly waste
- **Selection**: Auto-select Critical + Warning, allow user to adjust
- **Next Button**: "Analyze X Selected RIs"

#### Step 2: Recommendation Engine
- **Header**: "Optimization Recommendations"
- **For Each Selected RI, Show Card:**
  - **Current State**: Instance type, region, utilization chart
  - **Recommended Action** (automatically determined):
    - **If 0% utilization**: "Sell on Marketplace" or "Modify to different type"
    - **If <50%**: "Combine workloads" or "Right-size applications"
    - **If Convertible**: "Modify to match actual usage pattern"
  - **Impact Preview**: 
    - Current waste: $XXX/month
    - After action: $YYY/month (or recovered amount)
    - Net benefit: $ZZZ/month or $AAA one-time
  - **Effort**: Low/Medium/High badge
  - **Risk**: None/Low/Medium badge
  - **User Choice**: Accept / Modify / Skip
- **Summary Footer**: Total savings if all accepted: $X/month
- **Next Button**: "Review Plan"

#### Step 3: Execution Plan
- **Header**: "Optimization Plan Summary"
- **Timeline View**:
  - Gantt-style chart showing sequence of actions
  - Dependencies indicated (e.g., "Create new instance before terminating old RI")
  - Estimated duration for each step
- **Grouped by Action Type**:
  - **Marketplace Listings**: X RIs (estimated recovery: $Y)
  - **Modifications**: X RIs (will change to types: A, B, C)
  - **Workload Adjustments**: X RIs (require application changes)
- **Risk Assessment**:
  - Downtime estimate: "XX minutes expected"
  - Rollback plan: Automated description
- **Approval Required**: If governance rules apply, shows which approvers
- **Next Button**: "Execute Plan" or "Schedule Execution"

#### Step 4: Execution Monitoring
- **Header**: "Optimization in Progress"
- **Progress Bar**: Overall completion percentage
- **Live Activity Log**:
  - Timestamped entries
  - Color-coded by status (success, in-progress, warning, error)
  - Example: "14:32 - Listed ri-abc123 on Marketplace (asking $1,234)"
- **Pause/Cancel Controls**: Emergency stop if needed
- **Real-Time Savings Counter**: Incrementing as actions complete

#### Step 5: Completion Summary
- **Header**: "Optimization Complete"
- **Results Dashboard**:
  - Total savings realized: $X/month (with celebration visual)
  - Actions completed: Y/Z successful
  - Marketplace listings created: X (total value: $Y)
  - RIs modified: X
- **Next Steps Recommendations**:
  - "Monitor modified RIs for 30 days"
  - "Review marketplace listing performance weekly"
  - "Schedule next RI review for [date]"
- **Report Generation**: Download detailed PDF report
- **Close Button**: Return to RI tab (with refresh)

### **Wizard 2: S3 Lifecycle Policy Wizard**

**Entry Point:** "Optimize Lifecycle" button on S3 tab

#### Step 1: Bucket Selection
- **Header**: "Select Buckets to Optimize"
- **Filter Panel**: 
  - Buckets without policies
  - Buckets with suboptimal policies
  - All buckets
- **Bucket Cards Grid**:
  - Each card shows:
    - Bucket name + icon
    - Size (TB/GB) + object count
    - Current storage class distribution (mini bar chart)
    - Monthly cost
    - Savings opportunity badge
    - Checkbox for selection
- **Bulk Actions**: "Select All Without Policies", "Select Top 10 by Savings"
- **Next Button**: "Analyze X Buckets"

#### Step 2: Access Pattern Analysis (Auto-Run)
- **Header**: "Analyzing Access Patterns..."
- **Progress Indicators**: For each bucket:
  - Fetching access logs (if enabled)
  - Analyzing object age distribution
  - Calculating access frequency
  - Estimating optimal tiers
- **Results Display** (when complete):
  - **For Each Bucket, Show**:
    - Access pattern chart (scatter plot: Age vs Access)
    - Objects categorized:
      - Hot (keep in Standard): X objects, Y GB
      - Warm (move to IA): X objects, Y GB
      - Cold (move to Glacier): X objects, Y GB
      - Frozen (Deep Archive): X objects, Y GB
    - Recommended policy summary
- **Next Button**: "Configure Policies"

#### Step 3: Policy Configuration
- **Header**: "Configure Lifecycle Policies"
- **For Each Bucket, Interactive Timeline Builder**:
  - Visual timeline: Day 0 → Day 30 → Day 90 → Day 180 → Day 365+
  - Drag transition points to adjust:
    - Standard → Standard-IA (default: 30 days)
    - Standard-IA → Glacier (default: 90 days)
    - Glacier → Deep Archive (default: 180 days)
    - Delete after (default: never / or based on compliance)
  - **Policy Templates**: Quick apply buttons
    - "Aggressive Savings" (fast transitions)
    - "Balanced" (default)
    - "Conservative" (slower transitions)
    - "Compliance Hold" (no deletion, archive only)
  - **Exclusions**: Path-based rules
    - "Keep /thumbnails/ in Standard always"
    - "Exclude /temp/ from lifecycle (manual deletion)"
- **Cost Impact Simulator**:
  - Before: $X/month
  - After Month 1: $Y/month (policies take effect)
  - After Month 3: $Z/month (steady state)
  - Annual savings: $AAA
- **Next Button**: "Preview & Apply"

#### Step 4: Pre-Application Review
- **Header**: "Review Lifecycle Changes"
- **Summary Table**:
  - Bucket | Objects Affected | Current Cost | New Cost | Savings | Policy Actions
- **Warnings/Alerts**:
  - "X objects will become archived (retrieval fees apply if accessed)"
  - "Bucket Y has deletion rule - ensure compliance team approval"
- **Simulation Mode**:
  - "Test run this policy on sample data?"
  - Shows what would have happened if applied 90 days ago
- **Approval Routing**: If required, shows who will approve
- **Apply Options**:
  - Apply now (immediate effect)
  - Schedule for maintenance window
  - Staged rollout (10% of buckets, then review, then all)
- **Next Button**: "Apply Policies"

#### Step 5: Application & Monitoring
- **Header**: "Applying Lifecycle Policies"
- **Progress**:
  - Bucket-by-bucket application status
  - "Policy applied to bucket-X (12/15)"
- **Post-Application Dashboard**:
  - Policies active: X buckets
  - Objects in transition: Y
  - Estimated time to savings: Z days
- **Monitoring Setup**:
  - "Enable weekly email reports on policy effectiveness?"
  - "Set alert if storage costs increase unexpectedly?"
- **Next Steps**:
  - "Check back in 30 days to verify savings"
  - "Review access logs for any retrieval patterns"
- **Finish Button**: Return to S3 tab

### **Wizard 3: RDS Multi-AZ Removal Wizard**

**Entry Point:** "Optimize Multi-AZ" button on RDS tab

#### Step 1: Database Risk Assessment
- **Header**: "Multi-AZ Analysis"
- **Auto-Categorization**:
  - **Safe to Disable** (green section):
    - Databases tagged dev/test/staging
    - No active connections in 30 days
    - Backup snapshots enabled
    - List with checkboxes (pre-selected)
  - **Needs Review** (yellow section):
    - Production tag but internal tools
    - Low connection count
    - No formal SLA
    - List with checkboxes (not pre-selected)
  - **Keep Multi-AZ** (red section):
    - Production customer-facing
    - High traffic
    - PCI/HIPAA compliance tags
    - List (disabled checkboxes, informational only)
- **Manual Override**: Button to move database between categories
- **Next Button**: "Analyze X Databases"

#### Step 2: Impact Analysis
- **Header**: "Removal Impact Assessment"
- **For Each Selected Database**:
  - **Database Card**:
    - Name + engine + instance class
    - Current cost: $X/month (Primary: $Y, Standby: $Z)
    - Environment tag
  - **Pre-Flight Checks** (automated):
    - ✅ Automated backups enabled (RPO: X hours)
    - ✅ Point-in-time recovery active
    - ✅ No active connections during proposed window
    - ✅ Replica lag: 0 seconds (healthy)
    - ⚠ Last failover: Never / 365+ days ago (Multi-AZ unused)
  - **Risk Score**: Low / Medium / High (with explanation)
  - **Estimated Downtime**: 2-3 minutes during restart
  - **Savings**: $Z/month (50% reduction)
- **Aggregate Summary**:
  - Total databases to modify: X
  - Total monthly savings: $Y
  - Total expected downtime: Z minutes
- **Next Button**: "Schedule Changes"

#### Step 3: Scheduling & Notifications
- **Header**: "Schedule Multi-AZ Removal"
- **Timing Options**:
  - **Immediate**: Apply changes now (with confirmation)
  - **Maintenance Window**: Use existing DB maintenance window

## **SECTION 8: Performance & Loading States**

### Progressive Loading Strategy

**Hero Metrics First:**
- Load summary cards immediately (cached data)
- Show skeleton loaders for charts while data fetches
- Category tabs load counts in background (don't block UI)

**Table Virtualization:**
- Only render visible rows (50 at a time)
- Lazy load more as user scrolls
- "Load All" button if user needs full dataset

**Chart Streaming:**
- Start rendering chart with partial data
- Update as more data arrives
- Smooth transition animations

### Loading Indicators

**Skeleton Screens:**
- Replace spinners with content-shaped placeholders
- Pulsing animation to indicate loading
- Maintains layout stability (no shifting)

**Progress Indicators:**
- During scan: "Scanning region 3 of 12... 42% complete"
- During bulk action: "Processing 15 of 47 resources..."
- Time estimate: "~2 minutes remaining"

**Timeout Handling:**
- If operation >10 seconds: "This is taking longer than usual... still working"
- If operation >60 seconds: "Large dataset detected. Results will be cached for faster access next time."
- Offer to email results when complete

## **SECTION 9: Error States & Validation**

### Error Handling

**Graceful Degradation:**
- If scan fails for one region: Show partial results + warning banner
  - "Unable to scan us-west-2 (permission denied). Showing results for other regions."
- If cost data unavailable: Show resource counts without cost estimates
  - "Cost calculation temporarily unavailable. Contact support."

**Actionable Error Messages:**
- **Bad**: "Error 403"
- **Good**: "Access Denied: Your AWS credentials don't have permission to describe volumes. Grant ec2:DescribeVolumes permission and try again. [View IAM Policy]"

**Retry Mechanisms:**
- Automatic retry for transient failures (with exponential backoff)
- Manual retry button for user-initiated actions
- "Report Issue" button with pre-populated diagnostic info

### Validation

**Pre-Action Validation:**
- Before cleanup: Check resource still exists (prevent stale data issues)
- Before bulk action: Confirm user has permission for all selected resources
- Before wizard: Validate prerequisites (e.g., VPC Flow Logs enabled)

**Confirmation Dialogs:**
- For destructive actions: Require typing resource ID or "DELETE" to confirm
- Show impact preview: "This will delete 23 snapshots totaling 1.2 TB"
- Remember choice checkbox: "Don't ask again for safe resources"

## **SECTION 10: Accessibility & Responsiveness**

### Keyboard Navigation
- **Tab order** follows logical flow: Filters → Tabs → Table → Actions
- **Shortcuts**:
  - `/` - Focus search
  - `s` - Trigger scan
  - `r` - Refresh current view
  - `Esc` - Close modals/drawers
  - `Ctrl+A` - Select all visible
  - Arrow keys - Navigate table rows

### Screen Reader Support
- All charts have accessible data table fallback
- Table headers properly associated
- Button labels descriptive ("Delete 5 selected volumes" not just "Delete")
- ARIA live regions announce dynamic updates

### Responsive Breakpoints

**Desktop (>1200px)**: Full multi-column layout as described

**Tablet (768-1200px)**:
- Hero metrics: 2x2 grid instead of 4 columns
- Visualizations: Full width, stack vertically
- Table: Horizontal scroll enabled, pinned columns
- Wizards: Narrower modals, maintain step flow

**Mobile (<768px)**:
- Hero metrics: Single column, swipeable cards
- Tabs: Horizontal scrollable pills
- Table: Convert to card list:
  - Each resource as expandable card
  - Key info visible, tap to expand
  - Swipe gestures: Left = Actions menu, Right = Select
- Filters: Bottom sheet modal
- Wizards: Full-screen modals, simplified layouts
